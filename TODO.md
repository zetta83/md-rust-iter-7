### Задание

#### Шаг 0. Подготовка репозитория

- Создайте публичный репозиторий на GitHub для своего проекта.
- Создайте новый репозиторий для работы над смарт-контрактом на домашней машине
- Синхронизируйте его с публичным
- Все последующие изменения оформляйте отдельными коммитами — это поможет ревьюеру отслеживать ваш прогресс.

#### Шаг 1. Подготовить свой контур деплоя

Поднимите локальный валидатор (`solana-test-validator`), соберите программу (`anchor build`) и разверните её в локальной
сети.

#### Шаг 2. Деплой в Devnet

Конечная цель — развернуть готовую систему в Devnet и продемонстрировать её работу:

- Убедитесь, что программа задеплоена в Devnet.
- Обновите README.md в вашем репозитории, добавив:
    - адреса контрактов в Devnet;
    - 2-3 ссылки на успешные транзакции создания токенов.

#### Полный цикл на localnet

1. **Валидатор** (отдельный терминал, не закрывать):

```terminaloutput
make validator
```

Поднимает `solana-test-validator`. Убедитесь, что есть keypair и SOL: `solana airdrop 10` при необходимости.

2. **Сборка и деплой контрактов:**

```terminaloutput
make build
make deploy
```

3. **Инициализация oracle и minter** (один раз после деплоя):

```terminaloutput
make init
```

В выводе будет `ORACLE_STATE_PUBKEY` — скопируйте его в `backend/.env` (см. `backend/.env.example`).

4. **Backend** (второй терминал):

```terminaloutput
make backend
```

Нужен файл `backend/.env` с RPC, program ID и `ORACLE_STATE_PUBKEY`.

5. **Frontend** (третий терминал):

```terminaloutput
make frontend
```

Откройте в браузере URL из вывода dev-сервера. В кошельке выберите сеть Localhost / Custom RPC: `http://127.0.0.1:8899`.

#### Тесты

Когда всё починено и валидатор не занят (порт 8899 свободен):

```terminaloutput
make test
```

Запускаются LiteSVM-тесты (oracle + minter) без реальной сети.

**Итого:** `make install` → в одном терминале `make validator` → `make build` → `make deploy` → `make init` → в других
терминалах `make
backend` и `make frontend`. Проверка: `make test`.

Задание можно считать выполненным, если:

- у вас есть адреса программ, PDA и ссылка на успешную транзакцию в Devnet.

### Что проверяется в этом проекте

Проект проверяет именно те навыки, которым учили в модуле:

- CPI-вызовы к SPL Token Program.
- Безопасная математика и валидация данных.
- Деплой и настройка в реальной сети (Devnet).

### Как сдавать проект

Перед тем как отправить работу, убедитесь, что в вашем GitHub-репозитории:

1. Есть вся история разработки:
    - Первый коммит с исходной версией проекта.
    - Последующие коммиты.
    - Каждое значимое изменение оформлено отдельным коммитом.
2. В файле README.md указаны:
    - Адреса ваших контрактов в Devnet:
    - Program ID
    - 2-3 ссылки на успешные транзакции создания токенов в Devnet Explorer.
3. Проект полностью работоспособен:
    - Все тесты проходят (`make test`).
    - Полный цикл работает в Localnet (проверьте через justfile).
    - Система развёрнута и работает в Devnet.

### Процесс сдачи

1. Прикрепите ссылку на публичный GitHub-репозиторий и нажмите «Отправить».
2. Ревьюер проверит:
    - Историю коммитов и качество исправлений.
    - Работоспособность через тесты и документацию в README.
    - Корректность Devnet-развёртывания по указанным адресам.
3. При необходимости ревьюер создаст Issues с замечаниями.
4. Исправляйте каждое Issue отдельным коммитом (в заголовке укажите номер Issue).

Если возникнут вопросы по процессу сдачи — обращайтесь в чат курса. Удачи в сборке!
